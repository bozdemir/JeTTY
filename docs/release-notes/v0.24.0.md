# JeTTY v0.24.0

**Fullscreen.** A third window mode and a per-window `F11` toggle — designed from
a verified blueprint, stress-tested by two design critics against the winit
sources (15 blocking issues), then adversarially code-reviewed (3 more) and
screenshot-verified.

## Fullscreen mode

`Settings ▸ Window ▸ WINDOW MODE` now cycles **Center · Dropdown · Fullscreen**
(`window_mode = "fullscreen"`). It is a *summon policy*: every `F9` covers the
whole monitor the window is on — borderless, never changing your display mode.
Rounded corners square off while fullscreen (a radius would show the desktop
through four notches at the screen edges); your configured radius is untouched
and returns on exit, and the slider dims to say so.

## `F11` — toggle fullscreen on the focused window

Works on the main window *and* on a detached one, each independently. It is
transient: it never rewrites `window_mode` and never touches `config.toml`, so
there is no disk write on the key path — and the persisted mode wins on the next
summon, which makes an ad-hoc `F11` self-healing.

On **macOS** a companion **`Cmd+Ctrl+F`** is bound too, because bare `F11` there
is Mission Control's "Show Desktop" — and on Apple keyboards without *Use F1,
F2… as standard function keys* the physical F11 is Volume Down, so the app never
sees the key.

Also in the command palette (`Ctrl+Shift+P` → "Toggle fullscreen") and in the
Keyboard Shortcuts overlay.

## The one behaviour change

Bare `F11` no longer reaches the shell (it used to send `\e[23~`). Two escape
hatches, both pinned by tests:

```toml
[keys]
toggle_fullscreen = ""     # give bare F11 back to the shell
```

and — because the default chord is exact, not modifier-insensitive —
**`Shift`/`Ctrl`/`Alt`+`F11` still reach the PTY** as `\e[23;{m}~` regardless.

## Details worth knowing

- While a window is fullscreen its ▢ and a double-click on the top bar **exit
  fullscreen**, and dragging/resizing it is inert (including the resize cursor).
  Maximize and fullscreen stay orthogonal.
- Opening **Settings** or **detaching a tab** while fullscreen leaves fullscreen
  first — and going fullscreen while Settings is open closes Settings. A
  fullscreen window sits in the WM's above-normal layer, so a sibling window
  would otherwise be focused but invisible behind it (and Settings is the only UI
  for leaving the mode). Nothing is lost — every panel value is already saved.
- **On macOS only**, at most one JeTTY window is fullscreen at a time: macOS's
  simple-fullscreen overwrites *application-wide* presentation options, so two
  nesting windows can leave your Dock and menu bar auto-hidden everywhere. On
  X11/Wayland/Windows a fullscreen main window on one monitor and a fullscreen
  detached window on another are perfectly allowed.
- If your **window manager** fullscreens JeTTY on its own, JeTTY is not told (no
  such event exists) and its idea of the window's shape can go stale — `F11`
  re-syncs it.

## Performance, honestly

**Fullscreen is the most expensive window mode**, because GPU cost scales with
surface AREA: fullscreen on a 4K display is roughly 13× the pixels of the default
1000×640 window, and every pass scales with it — background quad, text, the
inline-image layer, and the CRT / summon-reveal effects worst of all. The only
saving is one skipped render pass (the corner mask, which has nothing to round).

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/bozdemir/JeTTY/main/install.sh | sh
```

Or a `.deb` / **AppImage** from the assets below (the installer verifies
`SHA256SUMS.txt`). Build from source: `cargo build --release`.
