# JeTTY v0.25.0

**Run selection in a new tab.** The browser gesture, transplanted: in a browser
you click a link and it opens in a new tab — in JeTTY you **select a command and
run it in a new tab**, opened in the selection's own directory. Designed from a
verified blueprint, stress-tested by two design critics (10 blocking issues),
adversarially code-reviewed (0 blocking) and screenshot-verified.

## Five triggers, one behaviour

- Right-click → **Run in New Tab** (dimmed without a selection, like Copy)
- **`Ctrl+Shift+Enter`** on the active selection (remappable: `[keys] run_selection`)
- The command palette → "Run selection in new tab"
- Copy-mode **`r`** — yank's sibling: select with `v`/`V`, run with `r`, never
  touching the mouse
- From a **detached window** — the tab opens in the main window at the detached
  tab's directory **without summoning or focusing anything**: a true background
  tab. If the main window is hidden it stays hidden, and **Run & Notify** pings
  you when the command finishes. That composition is the point: select a long
  command, fire it into a background tab, keep working, get the notification.

## Safety, paste-protection-grade

The selection is sanitized before it can touch a PTY — every control byte and
escape sequence is stripped (the bracketed-paste end marker cannot survive), then:

| Selection | What happens |
|---|---|
| single line | **runs** (bracketed paste, one accept-line after the close marker) |
| multi-line | **typed, not run** — staged at the new prompt awaiting *your* Enter |
| > 16 KiB | truncated and staged, never auto-run |
| multi-line, no bracketed paste | refused with a status pill — the tab still opens |

A selection ending in `\`, an unclosed quote, or a heredoc fragment parks at the
shell's continuation prompt (nothing executes) — JeTTY deliberately does not
parse shell syntax.

## Injection that waits for the shell

With OSC 133 shell integration the command is injected only once the new shell
shows its **first prompt with bracketed paste on** (powerlevel10k instant-prompt
safe). Without integration it falls back to a 1.5 s timeout — bracketed whenever
the shell supports it (multi-line stages there too). Typing, pasting, or an IME
commit into the new tab **cancels** the staged injection — you claimed the
prompt. A stale injection never fires (10 s TTL), and a status pill always tells
you why a tab is empty.

Opt out entirely with `run_selection = false` (hot-reloadable), or unbind just
the chord with `[keys] run_selection = ""`.

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/bozdemir/JeTTY/main/install.sh | sh
```

Or a `.deb` / **AppImage** from the assets below (the installer verifies
`SHA256SUMS.txt`). Build from source: `cargo build --release`.
