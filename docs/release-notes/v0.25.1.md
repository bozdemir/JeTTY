# JeTTY v0.25.1

**Run-selection, now usable where you actually live: inside Claude Code.**
v0.25.0's "select a command, run it in a new tab" assumed a plain-shell screen;
selecting from a mouse-grabbing TUI (Claude Code, vim, htop) hit two walls in a
row. This release removes both.

## The fixes

- **You couldn't select at all.** A mouse-grabbing app swallows the left-drag,
  so no JeTTY selection existed and the right-click menu's Copy / Run in New Tab
  sat dimmed with no explanation. The escape has always been **Shift+drag** —
  now JeTTY teaches it at the exact moment of failure: right-clicking over a
  mouse-grabbing app with no selection shows the *"Hold Shift while dragging to
  select text"* pill alongside the menu.
- **What you selected carried the frame.** Claude-Code-style bordered output
  drags its `│` edges (and doc-style `$ ` / `❯ ` prompt markers) into the
  selection, so the "command" arrived as garbage. Uniform decorations are now
  stripped automatically — strictly conservative, each rule firing only when it
  holds on **every** line of the selection:

  | You select | What runs |
  |---|---|
  | `│ $ cargo build │` | `cargo build` |
  | `$ cmd1` ⏎ `$ cmd2` | `cmd1` ⏎ `cmd2` (staged, multi-line) |
  | `echo $PATH` | `echo $PATH` — untouched |
  | mixed lines (`│ a` ⏎ `b`) | untouched, byte-for-byte |

  Stripping runs after sanitization and only ever shrinks the text; the
  paste-protection guarantees of v0.25.0 are unchanged.

So the flow inside Claude Code is now: **Shift+drag** the command →
right-click → **Run in New Tab** (or `Ctrl+Shift+Enter`) — it opens a tab in
the same directory and runs, borders and prompt markers stripped.

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/bozdemir/JeTTY/main/install.sh | sh
```

Or a `.deb` / **AppImage** from the assets below (the installer verifies
`SHA256SUMS.txt`). Build from source: `cargo build --release`.
